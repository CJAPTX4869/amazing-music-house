# 04 - 虚拟机部署方案（服务端上"云"）

> 目标：把 Spring Boot 后端 + MySQL + 歌曲文件全部部署到 CentOS Stream 9 虚拟机，
> 手机里的 koi_music 通过 `http://VM_IP:8080/api` 访问，宿主机恢复纯开发机。
>
> VM 信息：CentOS Stream 9 / root 登录 / 桥接模式 / 当前 IP `192.168.16.223`（DHCP）

---

## 一、架构

```
┌─ 宿主机 Windows（开发机）────────────┐
│  IDEA + 三端开发照常                  │
│  8080/5174/5175 本地跑，互不影响       │
└──────────┬─────────────────────────┘
           │ 桥接（同一手机热点局域网 192.168.16.x）
           ▼
┌─ 虚拟机 CentOS Stream 9（服务器）────┐
│  MySQL 8  →  music_db               │
│  JDK 11   →  music-server-1.0.0.jar │
│  /opt/music/storage（歌曲 4.6GB）    │
│  systemd 托管，开机自启、崩溃自拉      │
└──────────┬─────────────────────────┘
           │ http://192.168.16.223:8080/api
           ▼
    手机 koi_music（真机，连同一热点）
```

## 三、部署步骤

### 步骤 0：VM 装 JDK11 + MySQL8（VM 里执行）

```bash
dnf install -y java-11-openjdk mysql-server
java -version                      # 应显示 11.x
systemctl enable --now mysqld      # 启动并设开机自启
systemctl status mysqld --no-pager | head -3   # active (running) 即可
```

### 步骤 1：宿主机传 3 个文件到 VM（宿主机 PowerShell）

```powershell
scp D:\music_db.sql root@192.168.16.223:/root/
scp D:\storage.tar root@192.168.16.223:/opt/
scp D:\Desktop\MusicProject\music-platform\music-server\target\music-server-1.0.0.jar root@192.168.16.223:/opt/
```

- 首次连接问 `fingerprint` 输 `yes`，然后输 VM 的 root 密码
- 4.6GB 走热点局域网约 5~15 分钟（局域网直传，**不耗手机流量**）
- ⚠️ scp 不支持断点续传，中途断了就重跑那条命令

### 步骤 2：VM 里建库导数据

```bash
mysql -e "CREATE DATABASE IF NOT EXISTS music_db DEFAULT CHARACTER SET utf8mb4;"
mysql music_db < /root/music_db.sql

# ⚠️ 关键：给 root 设密码（jar 里配置是 root/root@localhost:3306）
# CentOS 的 MySQL 初装默认 root 免密（auth_socket），必须显式设置：
mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'root';"

# 验证：能查到歌曲数据 + 用密码能登录
mysql -uroot -proot music_db -e "SELECT COUNT(*) FROM song;"
```

### 步骤 3：VM 里放文件

```bash
mkdir -p /opt/music
tar -xf /opt/storage.tar -C /opt/music --strip-components=1   # 得到 /opt/music/storage/
mv /opt/music-server-1.0.0.jar /opt/music/
ls /opt/music/      # 应看到 storage 和 music-server-1.0.0.jar
du -sh /opt/music/storage   # ≈4.6GB
```

### 步骤 4：注册 systemd 服务（开机自启 + 崩溃自动拉起）

```bash
cat > /etc/systemd/system/music.service <<'EOF'
[Unit]
Description=Music Server (Spring Boot)
After=network.target mysqld.service

[Service]
WorkingDirectory=/opt/music
Environment=STORAGE_PATH=/opt/music/storage
ExecStart=/usr/bin/java -jar /opt/music/music-server-1.0.0.jar
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now music
journalctl -u music -f    # 看到 "Started MusicApplication" 即成功，Ctrl+C 退出跟踪
```

> **`STORAGE_PATH` 必须显式指定**：jar 直接放在 `/opt/music` 下时，
> 代码的"相对路径自动定位"会算错层级（解析到 /opt/storage），环境变量可直接覆盖，最稳。

### 步骤 5：放行防火墙 8080

```bash
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --reload
firewall-cmd --list-ports   # 应显示 8080/tcp
```

> 3306 不放行——MySQL 只需 VM 本机的 Java 连，不对局域网暴露更安全。

## 五、常见问题排查

| 症状 | 排查 |
|---|---|
| `systemctl start music` 失败 | `journalctl -u music -n 50` 看报错；十有八九是 MySQL 密码没设（步骤 2 的 ALTER USER） |
| MySQL 起不来 | `journalctl -u mysqld -n 50`；或 `mysqld --initialize` 后重试 |
| 接口 200 但封面/播放 404 | `STORAGE_PATH` 没生效：`systemctl show music -p Environment` 应含 `STORAGE_PATH=/opt/music/storage`；并确认 `/opt/music/storage/audio` 有文件 |
| 宿主机/手机连不上 8080 | VM 里 `firewall-cmd --list-ports` 看放行了没；`ss -tlnp | grep 8080` 确认在监听 |
| 手机 IP 变了连不上 | 手机热点重启后 DHCP 可能给 VM 换 IP → 手机浏览器进热点设备列表查新 IP；一劳永逸见第六节"固定 IP" |
| journalctl 中文乱码 | 正常（后端日志 GBK），不影响功能 |

### SELinux 说明

CentOS Stream 9 默认 enforcing，systemd 拉起的 java 属 unconfined 服务类型，读写 `/opt/music` 无需额外配置；若遇到莫名 Permission denied，先 `getenforce` 看，再 `ausearch -m avc -ts recent`。

## 六、日常运维

```bash
systemctl status music        # 看状态
systemctl restart music       # 重启
systemctl stop music          # 停止
journalctl -u music -f        # 实时日志（-n 200 看最近 200 行）
```

**更新后端版本**（以后改了代码要上 VM）：
```powershell
# 宿主机：重新打包 → 传 → VM 重启
cd D:\Desktop\MusicProject\music-platform\music-server
mvn clean package -DskipTests
scp target\music-server-1.0.0.jar root@192.168.16.223:/opt/music/
```
```bash
# VM：
systemctl restart music
```

**固定 VM IP（可选但建议）**：热点重开后 IP 会变。最简单方案是在 VM 里给 DHCP 配置加"请求固定地址"：
```bash
nmcli con mod ens33-dhcp ipv4.addresses 192.168.16.223/24
nmcli con up ens33-dhcp
```
（DHCP 仍工作，但每次优先请求 .223；手机热点的地址池一般会满足。）
