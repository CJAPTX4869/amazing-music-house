## 2. 服务端（music-server）严重问题

### 2.1 JWT 默认密钥 → 可离线伪造管理员 token（严重）
- **证据**：`application.yml:63` 提供了内置默认密钥（`${JWT_SECRET:…}` 的冒号后半段）；`JwtUtil.java:29-33` 直接用它做 HS256；`JwtInterceptor.java:95-103` 只验签，身份**完全取自 token 的 `sub`/`role`**，不回查数据库。
- **实测**：按默认密钥自签 `{sub:"1", role:1}` → `GET /api/admin/statistics` **HTTP 200 且返回全量统计**（songCount 218、onlineSongCount 216、userCount 8、diskUsed…）；用**不存在的** `sub=999999` 同样 200。
  对照组：错误密钥 → 401；过期 token → 401；`alg=none` → 401（验签本身有效，问题只在密钥可猜）。
- **影响**：任何读过仓库的人可无限期伪造任意管理员，完全接管管理端（上传/删除、封禁用户、读全量数据）。
- **修复**：① `secret: ${JWT_SECRET}` 去掉默认值 + 启动时校验（缺失或 <32 字节直接启动失败）；② **立即轮换密钥**（现存 token 全失效）；③ 拦截器按 `sub` 回查 `sys_user`（存在、`status=1`、`role` 以库为准），或把 `role` 从 token 移除。

### 2.2 内置管理员默认口令（严重）
- **证据**：`schema.sql:222-223` 的 `INSERT IGNORE INTO sys_user (...) VALUES ('admin', '<bcrypt hash>', '系统管理员', 1, 1);`，脚本注释里直接写了默认口令并提示"上线前必须修改"。
- **实测**：用该默认口令 `POST /api/auth/login` → **HTTP 200 登录成功**并返回 token。
- **修复**：部署期强制改密；脚本改为随机一次性口令并打印到部署日志；或加 `must_change_password` 首次登录强制改密；后台入口加来源限制。

### 2.3 禁用账号后 token 仍有效（严重）
- **证据**：`JwtInterceptor.java:86-104` 从不读 `sys_user.status`；`UserServiceImpl.java:102-104` 只在登录那一刻检查。
- **实测序列**（账号 id=19）：旧 token 请求 `/api/auth/profile` 200 → 管理员 `PUT /api/admin/users/19/status {"status":0}` 200 → **同一旧 token 再请求 200（`status:0`）**，且能用它 `POST /api/playlists` **创建成功（id=23）** → 随后已恢复启用。
- **影响**：封禁最长 24 小时（`app.jwt.expiration: 86400000`）内失效；配合 2.1 则策略完全无效。
- **修复**：Redis（6379 已在跑但后端未使用）存 `tokenVersion`：登录写入 claim，禁用时 `INCR`，拦截器比对。

## 3. 服务端（music-server）高危问题

### 3.1 私密歌单越权读取（高）
- 证据：`PlaylistServiceImpl.java:112-121` `detailPublic()` 只判空、**不校验 `status`**；`LegacyController.java:224-241` 的 `/playlist/detail`、`/playlist/track/all` 匿名可访问。
- 实测：`GET /api/users/1/playlists`（正确过滤）**不含 id=15**；但 `GET /api/playlist/detail?id=15`（匿名）返回 `{"name":"私密测试歌单", …}`，`/playlist/track/all?id=15` 同样 200。
- 修复：`detailPublic` 增加 `status==1 || 本人 || 管理员` 判定；legacy 层传 `UserContext.getUserId()`。

### 3.2 删除后同 MD5 文件永久无法再上传（高）
- 证据：`schema.sql:72-74` `UNIQUE KEY uk_md5 (file_md5)`（不含 `deleted`）；`Song.java:86-88` 的 `@TableLogic` 让 `findOneByMd5` 永远看不到软删行；`SongServiceImpl.java:145-157` 冲突后抛 `FILE_WRITE_FAILED`。
- 实测：上传 → 删除 → `check-md5` 返回 `data:null` → **用同一文件再上传必得 `{"code":1004,"上传失败，请重试"}`**，错误信息完全掩盖真实原因。
- 修复（择一）：唯一索引改 `(file_md5, deleted)`；或软删时置空 `file_md5`；或冲突后忽略逻辑删除再查并复位 `deleted=0`；提示改为可定位原因。

### 3.3 Range 越界/畸形返回 500（高）
- 证据：`SongController.java:179-205` 手工计算 Range，未处理 `end<start`、越界、解析异常。
- 实测（歌曲 5，fileSize 82894410）：
  - `bytes=0-0` → 206 正常；`bytes=-5` → 206 正常
  - `bytes=999999999-` / `bytes=999999999-1000000000` / `bytes=abc` / `bytes=10-5` / `bytes=--5` → **全部 `{"code":500}`**
  - `bytes=82894410-` → 206 但 `Content-Length: 0` 且**无 Content-Range**
  - `bytes=0-1,5-6` → 只返回第一段（多段被静默忽略）
- 修复：改用 `HttpRange.toResourceRegions(ranges, resource)`（内置 416 校验），不可满足显式 416。

### 3.4 参数类型不匹配一律 500（高）
- 实测全部 `HTTP 200 + {"code":500}`：`/songs/abc`、`/songs/99999999999999999999`（Long 溢出）、`/users/abc/profile`、`/check/music?id=abc`、`/song/url/v1?id=abc`、`/lyric/new?id=abc`、`/top/song?limit=abc`、`/cloudsearch?offset=abc`、`/playlist/detail?id=abc`、`/like?id=abc`。
- 另：旧前端 `service/songs.ts:36-37` + `stores/main.ts:277` 会发出 `id=undefined`（`run.log` 记录 8 次）→ 播放链路首步失败，用户表现为"无故跳歌"。
- 修复：`GlobalExceptionHandler` 增加 `MethodArgumentTypeMismatchException`/`TypeMismatchException` → 400；前端补空值守卫。

### 3.5 multipart 缺 `file` 参数返回 500（高）
- 实测（带合法 token、无 body）：`POST /api/users/avatar`、`/api/comments/image`、`/api/songs/5/lyric`、`/api/songs/5/cover`、`/api/playlists/1/cover` → **全部 500**（连"无权操作他人歌单"的 403 都没机会执行）。
- 修复：增加 `MultipartException`/`MissingServletRequestPartException` → 400「缺少上传文件」。

### 3.6 业务错误全部 HTTP 200（高）
- 实测状态行：无 token 访问 `/admin/statistics` → `200 | {"code":401}`；普通用户 → `200 | {"code":403}`；`/songs/0` → `200 | {"code":404}`；`/songs?size=0` → `200 | {"code":400}`；`/nosuch/endpoint` → `200 | {"code":404}`。
  只有直接构造 `ResponseEntity` 的二进制接口返回真实码（`/songs/999999/cover` → 404、`/users/999999/avatar` → 404）。
- 影响：网关/WAF/监控/DevTools 一律看到 200，越权与故障不可见；前端若用 `fetch().ok` 判断会误判成功。
- 修复：错误分支返回 `ResponseEntity.status(...)` 或 `@ResponseStatus`；过渡期可先加 `X-Biz-Code` 响应头。
- **注意**：本项目两个前端（`vue3-cloud-music-master/src/service/request.ts:48`、`music-web/src/api/request.ts:65`）都**只处理业务码 401**，其它业务错误码（404/500）静默通过 → 调用方拿到 `data:null` 可能崩。

### D.3 本轮踩过的坑（教训，供后续"严谨"执行参考）

1. **PowerShell 用正则改文件时，`\r\n` 与 `\n` 不匹配会导致静默失败** ✗ → 造成"改了但没生效"（创建按钮、列宽、拦截器钩子都中过一次）。**规矩：改文件一律按行定位 + 改完回读核对**。
2. 正则跨方法匹配把 `update()` 与 `uploadCover()` 串行 → 编译失败 → 只能按行重建方法。
3. NSIS 的 `artifactName` 误写成 `.msi` 结尾 → **NSIS 安装器覆盖了同名 MSI 文件**。
4. 后端运行中执行 `mvn package` → jar 改名失败，留下 0.2 MB 残包 → 必须先停后端。
5. 启动器与静态服务共写一个日志文件 → 文件锁导致日志丢失 → 拆分 `launcher.log`/`server.log`。
6. **`.vbs` 必须纯 ASCII 或 UTF-16+BOM**（wscript 按 ANSI 读，UTF-8 中文会语法错误 800A0400）。
7. Spring Boot fat jar 的 `getCodeSource().getLocation()` 是嵌套 URL → `Paths.get(uri)` 抛异常 → 存储目录回退到工作目录（换位置就丢文件）。
8. `file://` 页面读不到同目录 `config.json`（Chromium 限制）→ Electron 用 preload 注入；Edge 应用模式必须经本地 HTTP 服务。
9. PowerShell 5.1 不支持 `??`；`for(){...} | Select-Object` 会报"空管道"。
10. **`ConvertFrom-Json` 读 UTF-8 无 BOM 文件会乱码误报** ✗ → 校验 JSON 用 `node -e "require('./package.json')"`。
