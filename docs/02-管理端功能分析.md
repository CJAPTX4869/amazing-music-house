# 02 · 管理端功能分析

> 分析对象：`D:\Desktop\MusicProject\music-platform\music-web\`
> 定位：面向**管理员**的后台界面 —— 上传歌曲、维护歌曲库、管理用户。技术栈：Vue 3 + TypeScript + Vite 5 + Element Plus + Pinia。
> 端口：**5174**（dev）。启动：`npm run dev`。请求通过 Vite 代理 `/api` → `http://localhost:8080`，**无跨域问题**。
> 与客户端的关系：共用同一个后端与数据库；管理端改动后客户端需刷新可见（无实时推送）。

## 2. 路由表

| 路径 | 页面 | 守卫 | 说明 |
| --- | --- | --- | --- |
| `/login` | LoginView | 已登录则跳走 | 登录/注册 |
| `/songs` | SongLibraryView | — | 默认页：歌曲库 |
| `/upload` | SongUploadView | **requiresAdmin** | 上传歌曲 |
| `/admin/songs` | SongManageView | **requiresAdmin** | 歌曲管理 |
| `/admin/users` | UserManageView | **requiresAdmin** | 用户管理 |
| 其余 | NotFoundView | — | 404 |

守卫要点：刷新后若"有 token 无 userInfo"会先调 `/auth/profile` 恢复；未登录访问受保护页 → 带 redirect 跳登录；非管理员访问管理页 → 回歌曲库。**真正的权限边界在后端 `@RequireAdmin`，前端只做体验拦截。**

## 4. 数据流与状态管理

### 4.1 请求层（`api/request.ts`）

```
baseURL: /api            ← Vite 代理转发到 http://localhost:8080（同源，无 CORS 问题）
authToken：导出的共享响应式 ref
  ├─ 请求拦截：有 token → Authorization: Bearer
  └─ 响应拦截：body.code===401 → setAuthToken('')（store.isLogin 立即变 false → 守卫放行登录页）
```

设计要点（历史踩坑）：401 时**不能只清 localStorage** —— 必须同时清共享 ref，否则 `isLogin` 仍是 true，路由守卫会把用户挡回首页、永远进不去登录页（已修复）。

### 4.2 文件上传的约定

- 批量上传**串行逐个**：一次请求多文件会撞 `max-request-size`（110MB）限制
- 封面/头像先在前端压缩（`compressToSquare`：600²/512²，JPEG，白底防透明发黑），后端只校验格式与大小
- 封面 URL 带 `?v=updateTime` 破浏览器缓存

## 7. 已知问题与注意事项

1. `getStatistics` 已封装但**没有任何页面调用**（后续可做数据看板）。
2. 批量上传必须**串行**，改成并发会触发后端 `max-request-size` 限制。
3. 上传接口要求 `@RequireAdmin`：普通用户登录后菜单里看不到"上传/管理"，直接访问路由也会被守卫挡回。
4. 用户头像接口为协商缓存（`no-cache` + Last-Modified），设置头像后列表用 `?v=时间戳` 破缓存。
5. 歌曲库试听播放器（AudioPlayer.vue）依赖后端 `/stream` 支持 Range（已支持，可拖进度）。
6. `.npmrc` 里遗留的 `only-built-dependencies` 配置 npm 已不识别（仅警告，无影响）。
