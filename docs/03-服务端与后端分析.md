# 03 · 服务端与后端分析

> 分析对象：`D:\Desktop\MusicProject\music-platform\music-server\`
> 定位：**一个 Spring Boot 进程同时承担两层职责** —— 「服务端」= 业务逻辑（Controller/Service：谁能改什么、数据怎么校验），「后端」= 支撑机制（Tomcat、鉴权拦截器、连接池、文件流、日志、定时任务、部署）。
> 技术栈：Java 11 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.7 + Druid/Hikari + MySQL 8（`music_db`）+ JWT(jjwt 0.11.5) + jaudiotagger + hutool。
> 端口：**8080**，统一前缀 `/api`（`server.servlet.context-path`）。启动：IDEA 运行 `MusicApplication` 或 `mvn spring-boot:run`。

## 2. 接口总表（40+ 条，逐条）

> 权限：`公开` = 无需登录；`登录` = @RequireLogin；`管理员` = @RequireAdmin。

## 4. 横切机制（后端支撑能力）

| 机制 | 实现 | 要点 |
| --- | --- | --- |
| **统一响应** | `Result{code,message,data,timestamp}` + `ResultCode` 常量 | 业务错误 HTTP 200 + 错误码；流式接口例外 |
| **全局异常** | `GlobalExceptionHandler`（@RestControllerAdvice） | 业务异常→对应错误码；未预期异常只记日志返回通用提示；**流式响应保护**：响应已提交→放弃写体；已按二进制响应→reset 为 404（防二次异常产生 500 空体） |
| **鉴权** | `JwtInterceptor` + `UserContext`(ThreadLocal) + `@RequireLogin/@RequireAdmin` | 无状态 JWT（24h）；解析即填上下文，请求结束清理；权限是**唯一安全边界** |
| **密码与限流** | BCrypt 存储；内存限流（5 次失败锁 10 分钟，定期清理） | 不区分"用户不存在/密码错误"；多实例需换 Redis |
| **文件存储** | `FileStorageService(Impl)` | 相对路径自动基于**类文件位置**定位项目目录（抗工作目录漂移与项目移动）；UUID 重命名+日期分片；MD5 计算；路径穿越防护；磁盘余量校验；四类文件独立目录与白名单（audio 100MB / cover 5MB / lyric 1MB / avatar 2MB） |
| **异步** | `AsyncConfig` 线程池 + `recordPlayAsync/recordDownloadAsync` | 播放/下载计数不阻塞文件流 |
| **自动填充** | `MyMetaObjectHandler` | insert/update 自动写 create_time / update_time |
| **CORS** | `CorsConfig` | 允许 5175 跨域；暴露 Content-Disposition |
| **日志** | Slf4j/logback；MyBatis SQL DEBUG 全量 | 文件为 **GBK** 编码（PowerShell 读取需 `-Encoding Default`） |
| **定时任务** | `DiskMonitorTask`（磁盘余量监控）、`OrphanFileCleanTask`（孤儿文件清理） | 运维保障 |
| **元数据** | `AudioMetadataUtils`（jaudiotagger） | 上传时自动读取时长等写入歌曲记录 |

## 6. 关键业务流程（代码视角）

**上传歌曲**（`SongServiceImpl.upload`）：
校验文件（validate）→ 计算 MD5（重复即秒传拒绝/返回）→ `FileStorageService.store` 落盘 → 读音频元数据（时长）→ 入库 → 返回 SongVO。**入库失败会删除已落盘文件（补偿回滚）**。

**替换封面**（`uploadCover`）：新文件落盘 → 更新 cover_path → **删除旧封面** → 失败补偿回滚。

**播放**（`SongController.stream`）：`getPlayableSong`（存在+上架）→ `loadSongResource`（文件缺失→404，不进流式阶段）→ 按请求 Range 计算 `ResourceRegion` → 206 输出 → 首段异步计播放数。

**歌曲删除**：逻辑删除记录 → 物理删除 audio/cover/lyric 文件 → 孤儿文件由 `OrphanFileCleanTask` 兜底清理。

## 7. 已知问题与注意事项

1. **401 语义**：业务错误恒 HTTP 200 + `code`；流式/图片接口用真实 404/206。前端必须区分处理。
2. **日志文件 GBK 编码**：读取需 `-Encoding Default`。
3. **存储路径**：`application.yml` 用相对路径 + `projectDir()` 自动定位；**不要改回绝对路径**（项目移动会失效）。
4. `updateUserInfo` 仅支持昵称/签名；性别/生日/地区无数据源（前端已标注）。
5. `/admin/statistics` 接口就绪，管理端暂无看板页面。
6. 登录限流是单机内存实现，多实例部署需换 Redis。
7. `PlaylistController` 的公开详情接口路径以实际代码为准（`/playlists/{id}/public` 与旧前端的 `/playlist/detail` 是两条独立链路）。
