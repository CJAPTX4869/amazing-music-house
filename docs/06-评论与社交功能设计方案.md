> 状态：**待确认**（确认后按第四节计划分阶段开工）
> 需求来源：2026-09-18 用户需求（网易云样式评论、999+/w+ 角标、表情包、两层嵌套追评、个人主页、好友式关注、收藏他人歌单；分享暂不做）

| # | 需求 | 方案落点 |

## 二、数据库设计（新增 4 表 + 3 字段，全部遵循现有 schema 风格）

### 2.1 新增表

```sql
-- 歌曲评论（根评论与楼中楼回复共用一张表）
CREATE TABLE IF NOT EXISTS song_comment (
  id            BIGINT      PRIMARY KEY AUTO_INCREMENT,
  song_id       BIGINT      NOT NULL COMMENT '歌曲',
  user_id       BIGINT      NOT NULL COMMENT '评论人',
  parent_id     BIGINT      DEFAULT NULL COMMENT '父评论 id；NULL=根评论，回复统一指向根评论',
  reply_user_id BIGINT      DEFAULT NULL COMMENT '被回复用户（楼中楼显示 回复@xx）',
  content       VARCHAR(1000) NOT NULL COMMENT '内容（含 [表情名] 占位符）',
  image_path    VARCHAR(500) DEFAULT NULL COMMENT '配图相对路径（单图，可为 GIF）',
  like_count    INT         NOT NULL DEFAULT 0,
  create_time   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted       TINYINT     NOT NULL DEFAULT 0,
  KEY idx_song_time (song_id, create_time),
  KEY idx_parent (parent_id),
  KEY idx_user (user_id)
) COMMENT='歌曲评论';

-- 评论点赞（物理删除，UNIQUE 防并发重复）
CREATE TABLE IF NOT EXISTS comment_like (
  id         BIGINT   PRIMARY KEY AUTO_INCREMENT,
  comment_id BIGINT   NOT NULL,
  user_id    BIGINT   NOT NULL,
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_comment_user (comment_id, user_id),
  KEY idx_user (user_id)
) COMMENT='评论点赞';

-- 好友式关注（A 发请求 → B 同意后 status=1，双向互为好友；拒绝则删行）
CREATE TABLE IF NOT EXISTS user_follow (
  id          BIGINT  PRIMARY KEY AUTO_INCREMENT,
  requester_id BIGINT NOT NULL COMMENT '发起方',
  target_id    BIGINT NOT NULL COMMENT '接收方',
  status      TINYINT NOT NULL DEFAULT 0 COMMENT '0-待对方处理 1-已互关',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_requester_target (requester_id, target_id),
  KEY idx_target (target_id)
) COMMENT='好友关系';

-- 收藏他人歌单（与"把歌收进歌单"的 playlist_song 语义严格区分）
CREATE TABLE IF NOT EXISTS playlist_collect (
  id          BIGINT   PRIMARY KEY AUTO_INCREMENT,
  user_id     BIGINT   NOT NULL,
  playlist_id BIGINT   NOT NULL,
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_playlist (user_id, playlist_id),
  KEY idx_playlist (playlist_id)
) COMMENT='收藏的歌单';
```

### 2.2 既有表加字段

| 表 | 字段 | 用途 |
|---|---|---|
| song | `like_count INT DEFAULT 0` | 列表角标（favorite/unfavorite 时 ±1，附一次性存量重算 SQL） |
| song | `comment_count INT DEFAULT 0` | 列表角标（评论增删时维护） |
| playlist | `collect_count INT DEFAULT 0` | 个人主页歌单网格角标 |
| sys_user | `region VARCHAR(100) DEFAULT NULL` | 个人主页"地区"（UserInfoEdit 前端本就有省市选择，只是从未提交） |

### 2.3 隐私边界（简单可靠）

- 个人主页对**所有人**可见；歌单按 `status` 过滤（私有歌单不出现在他人主页）
- 「我喜欢的音乐」跟随歌单 `status`（默认公开，可编辑为私密）

## 三、接口与前端设计

### 3.1 新增接口（全部遵循现有 Result/PageVO/@RequireLogin/@PublicApi 模式）

**评论**（新建 CommentController/Service/Mapper）
```
GET    /songs/{songId}/comments?page&size&sort=hot|new   @PublicApi 匿名可浏览（登录则带 liked 标记）
POST   /songs/{songId}/comments        {content, imagePath?}        发根评论/配图
POST   /comments/{id}/replies          {content, replyUserId?}      楼中楼回复/追评
DELETE /comments/{id}                  本人或管理员；删根=整楼隐藏
POST   /comments/{id}/like  / DELETE   点赞/取消（like_count ±1）
POST   /comments/image                 配图上传（jpg/png/webp/gif ≤5MB，GIF 不压缩保动画）
GET    /comments/{id}/image            @PublicApi 图片直出
GET    /emojis                         @PublicApi 表情清单（名字→图片地址）
POST   /admin/emojis                   @RequireAdmin 上传表情图（统一压到 96×96 PNG）
```

**关注（好友请求制）**
```
POST   /users/{id}/follow              发出好友请求（pending；重复/自己 → 业务码拦截）
POST   /users/{id}/follow/accept       同意（status→1，双方互为好友）
DELETE /users/{id}/follow              拒绝（pending）或解除好友（accepted）
GET    /users/{id}/follow/status       我与该用户的关系（无/pending/好友）
GET    /users/follow/requests          我收到的待处理请求（页头红点数据源）
```

**收藏他人歌单**
```
POST/DELETE /playlists/{id}/collect     不能收藏自己的；仅公开歌单
GET    /playlists/{id}/collect/check    是否已收藏（按钮状态）
```

**个人主页**
```
GET /users/{id}/profile      @PublicApi 资料+关注粉丝数+是否好友/是否本人
GET /users/{id}/playlists    创建的歌单（type=0 公开）+「我喜欢的音乐」歌单
GET /users/{id}/collects     收藏的歌单（公开）
```

**既有接口改造**：Legacy `/user/playlist?uid=` 与 `/likelist?uid=` 目前**忽略 uid**，改为"uid 为空取当前用户，否则查目标用户"，并把**收藏的歌单**并入返回（前端按 `creator.userId===我` 区分创建/收藏分组）。

### 3.3 评论嵌套与"追评"规则（明确版）

- 存储统一：`parent_id` 恒指向**根评论**，`reply_user_id` 记录被回复人
- 显示统一两层：根评论 → 楼中楼平铺列表，条目前缀"回复 @昵称："
- 任何人（含根评论主）都能在楼中楼继续追评 = 新增一条同 `parent_id` 的记录 → **无深度限制的技术债务、天然满足"最多嵌套 2 次"的显示要求**
- "精彩评论" = `like_count` 降序（同数按时间）；"最新评论" = 时间倒序；根评论分页，楼中楼随根一次带出

### 3.4 表情包方案（需要你拍板，见 §5）

- 存储：评论内容为纯文本 + `[表情名]` 占位符（官方同款，防 XSS、可检索），渲染层替换为图片
- 图片：后端 `GET /emojis` 返回名字→图片地址清单；图片走 `@PublicApi` 接口直出（项目已关闭静态资源映射）
- 上传：管理端上传后**统一压缩到 96×96 PNG**（满足"本地图片压缩成统一规格"）

## 五、需要你拍板的 3 个决策点

1. **表情包初始数据**：
   - A. 先用 Unicode emoji 字符面板（零资产、立即可用），图片表情机制做好等你提供图包
   - B. 我直接下载一套开源 Twemoji（约 72 个常用表情，CC 授权）做成图片表情，一步到位（推荐，最接近你说的"图片代替 emoji"）
2. **隐私范围**：个人主页与「我喜欢的音乐」对所有人可见（按歌单"公开/私密"开关过滤），还是"喜欢的音乐仅好友可见"？（推荐前者=官方行为，实现也最稳）
3. **好友请求的通知入口**：放页头用户气泡里（轻量，推荐），还是单独做一个"消息中心"页？（消息中心=更大工程，建议 V2）
